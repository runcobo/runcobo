# Runcobo with crsql

This runnable PostgreSQL application connects request-validation contracts to
queries generated by [crsql](https://github.com/shootingfly/crsql). It includes
author creation, reading, partial updates, and a two-write transaction that
creates an author and a book.

The framework stays independent of database drivers. This application adds `pg`;
the generator is a development dependency. The compiled server needs neither
crsql nor sqlc at runtime.

## Install and run

Use Crystal 1.22.x, Shards, PostgreSQL, and sqlc 1.31.1. Both request-validation
and crsql are private repositories; your authenticated Git connection must have
read access to them. From this directory:

```sh
shards install
shards build crsql
./bin/crsql generate
shards build server

createdb runcobo_crsql_development
psql postgres://localhost/runcobo_crsql_development -v ON_ERROR_STOP=1 -f db/schema.sql
DATABASE_URL=postgres://localhost/runcobo_crsql_development ./bin/server
```

The example's `shard.lock` pins dependency versions. Its `runcobo` dependency
uses the repository root (`../..`); replace that path with your framework
repository/version when copying this application elsewhere.

`db/schema.sql` is a starting schema, not a migration runner. Apply it once to
an empty development database. Generation parses this file and `db/queries.sql`;
it does not create or modify database tables. Use your application's migration
process for later schema changes.

The generated `src/db/queries.cr` is committed. Change the schema or named
queries and regenerate it; do not edit the output by hand.

## Try the endpoints

```sh
curl -i http://127.0.0.1:3000/authors \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ada","bio":"Writer"}'

curl http://127.0.0.1:3000/authors/1
curl http://127.0.0.1:3000/authors

# Omitted bio is preserved.
curl -X PATCH http://127.0.0.1:3000/authors/1 \
  -H 'Content-Type: application/json' -d '{"name":"Ada Lovelace"}'

# Explicit null clears bio.
curl -X PATCH http://127.0.0.1:3000/authors/1 \
  -H 'Content-Type: application/json' -d '{"bio":null}'

curl -i http://127.0.0.1:3000/author-books \
  -H 'Content-Type: application/json' \
  -d '{"name":"Grace","title":"Notes","isbn":"book-1"}'
```

Invalid inputs return the framework's structured validation errors before any
query runs. Missing authors return 404. Partial updates use the contract's
presence flags, so an omitted field and an explicit null produce different
query parameters. An empty update and a null name return 422.

`POST /author-books` executes both writes with the transaction-scoped query
object, and renders the response after the transaction commits. A duplicate
book identifier returns 409 and rolls back the new author as well as the book.
Other database errors continue to propagate instead of being mislabeled as
validation failures or identifier conflicts.

## Connection ownership and injection

`src/main.cr` opens one application pool with `CrSQLExample::Store.open` and
passes its query object to `CrSQLExample.handlers`. The pool closes when the
server scope exits normally or raises.

`StoreRouteHandler` overrides the framework's protected `build_action` hook to
attach that query object to the application's own base action. There is no
framework-global pool or store. Each handler may receive its own store, including
one created with `queries.with_transaction(transaction)` for caller-managed
transactions. Transaction-scoped stores stay within their transaction block.

Pass custom handlers to `Runcobo.start(handlers: ...)` or
`Runcobo::Server.new(handlers: ...)`. Handler assignment is also supported before
binding sockets; replacing handlers after binding is rejected.

Generated rows remain data-access results. Actions explicitly select the fields
they return to clients, without adding response serialization to generated code.

## Development checks

From the repository root:

```sh
make generate
make generate-check
make check

createdb runcobo_crsql_test
psql postgres://localhost/runcobo_crsql_test -v ON_ERROR_STOP=1 -f examples/crsql/db/schema.sql
DATABASE_URL=postgres://localhost/runcobo_crsql_test make integration
```

Integration tests require the database name `runcobo_crsql_test` and truncate
the example's `authors` and `books` tables. Use a dedicated test database. They
cover request-to-query round trips, missing rows, omitted/null updates, commit
and rollback, caller-managed and nested transactions, handler isolation,
single-connection pools, actual server requests, and pool cleanup.

Automated checks regenerate and compare the output, run the framework checks,
and run this integration suite against PostgreSQL 16 on both supported Crystal
versions. Private generator checkout uses the separate read-only `CRSQL_SSH_KEY`
repository secret; the existing `REQUEST_VALIDATION_SSH_KEY` remains separate.
